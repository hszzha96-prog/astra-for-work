# 工作复盘是记录

第二阶段把常做的 20 项工作按用途分配到四组，再记录跨组环节。一个条目可以只属于一组，同时向别组提供材料、反馈或结果。

**打开演示**　下载仓库并解压，用浏览器打开本目录的 [index.html](index.html)。文件自带数据、样式和渲染程序，可离线运行。在 GitHub 的文件页点选该链接时，看到的是源代码。若要通过本地 HTTP 浏览，在仓库根目录执行以下命令，再访问终端所示端口的 `/atlas/`。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

## 看一段跨组交接

1. 打开页面，从金色的 **Teams 小组协作** 开始。这里用 Teams 表示小组反馈与分工这个环节。
2. 让漫游依次点亮办公组。在办公与设计交界处，镜头先拉远，再推近橙色星团的「胶片调色与修图」。这个顺序用于浏览清单。
3. 点击「查看全图」，在目录中选择「Teams 小组协作」。点击其详情中的「组员反馈 → 讲稿转场」，镜头聚焦 **演示稿与图表设计**。这条连线记录小组反馈怎样成为讲稿衔接的具体修改。
4. 在演示设计详情中点击「预测结果 → 汇报图表」，可以沿关系反向追到 **PAL 需求预测**。现在可以解释汇报中的模型比较图来自哪项工作。

在桌面拖动空白处旋转视角，滚轮或右下角按钮缩放。在触屏上用单指旋转、双指缩放。点击「暂停漫游」后，也能用上一项、下一项手动推进。开启系统“减少动态效果”时，页面等待手动播放。

## 四组工作如何分配

| 分类中心 | 组内 5 项工作 |
| --- | --- |
| 金色 · 办公协作 | Teams 小组协作、Dropbox 资料归档、资讯收集与整理、日常工作复盘、日程与学习提醒 |

全图包括 **1 个 Codex 根节点、4 个分类中心、20 个工作节点**。4 条根到分类的线和 20 条分类到工作的线表示归属。另有 7 条跨组关联，全图合计 **25 个节点、31 条连线**。

## 每条跨组关系记录了什么

| 起点 | 终点 | 用途 |
| --- | --- | --- |
| Teams 小组协作 | 演示稿与图表设计 | 把组员反馈用于修改讲稿转场。 |
| Dropbox 资料归档 | ABD 开卷手册 | 调取讲义，为每周手册提供原文。 |
| Dropbox 资料归档 | 双重曝光配片 | 从图库取出可叠合的原片。 |
| PAL 需求预测 | 演示稿与图表设计 | 将基线和模型的比较结果做成汇报图表。 |
| 日程与学习提醒 | Consumer 与 Platform 自学 | 按每日提醒开始章节练习。 |
| 日程与学习提醒 | 新加坡岗位扫描 | 按每周提醒扫描新机会。 |
| 资讯收集与整理 | 面试题库与模拟问答 | 把收集到的面经转成练习材料。 |

网页保留这一阶段的自包含快照。若准备做网络查询、布局导出或其他设计实验，从下一阶段的 [passway extra work 模型](../model/README.md) 读取结构化数据。这里的“点亮”表示本次已浏览至该项，不能据此推算工时或任务完成率。
