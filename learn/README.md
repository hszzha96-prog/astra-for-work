# staring技术学习

最初想弄懂的是，当一个插件从目录中被选中时，为什么观众能先看到那个金色光点，又能在镜头拉远后认出它属于哪一组？这一步把观察拆成可复用的指令。

## 从哪里看出层级

参考画面里，Teams 附近有发光的选中环，办公类条目聚在金色区域。画面推进到设计工具时，另一片橙色区域开始出现。第一帧显示 3 项工具、5 个图节点。数到中间的 Codex 与办公分类中心，恰好补足两个节点。复刻时，可以让根节点连接分类中心，再将每个条目连回所属分类。原视频的作者、具体软件和网页是否可以拖动，仍待原工程或制作说明确认。

| 观察 | 可以写成怎样的要求 | 如何检查成品 |
| --- | --- | --- |
| 同一用途的工具成团 | 先标明成员所属分类，再在空间中为每组指定中心，给组内节点留出距离。 | 拉到全景时，同色成员聚在一起，组与组之间留有空隙。 |
| 当前工具比其他点突出 | 当前点显示同色双环，点名跟随它。类别中心保留一个独立标记。 | 视线能从列表的选中行移到图中同一个点。 |
| 动态镜头带出类别变化 | 换组时先显出两个星团的位置关系，然后推近新组中的目标点。 | 暂停在转场中段，可以同时看见前后两组。 |
| 关系线承载信息 | 将分类归属与跨组协作画成两种线。为每条跨组线写明用途。 | 点开条目后能读出这条线两端为何相关。 |

## 第一轮技术指令

最初的提示词要求生成一个单文件 HTML，用 Three.js 绘制发光节点，用 d3-force-3d 安排空间位置。以下是当时写在提示词中的实验设定。

| 实验项目 | 初始设定 |
| --- | --- |
| 数据和连线 | 20 个示例节点分成 4 组，节点含 `id`、`group`、`importance`。随机生成连线，并保证整张图连通。 |
| 布局 | 电荷力强度 `charge = -300`，连线目标长度 `linkDistance = 80`，碰撞半径 `collide radius = 15`。 |
| 光效与出场 | 加法混合叠加光晕，自定义材质用 `uTime` 驱动透明度在 0.6–1.0 之间正弦波动。页面加载的前 2 秒，节点从中心向外扩散。 |
| 交互 | OrbitControls 启用阻尼。悬停查看名称和分组，点击高亮相邻连线，左侧选中后镜头平滑移向该节点。 |

这些参数记录的是学习时的试验起点。第二阶段将 20 个示例换成具体工作，另加 4 个分类中心和 1 个根节点。随机连线被 24 条归属关系与 7 条逐一说明用途的跨组关系取代，出场顺序改为按组逐项点亮。

## 转入实际工作后的原始指令节选

以下两句摘自本项目早期的制作要求。

> 每个条目连回所属分类，跨组连线只用于有明确含义的关系。

> 远景优先显示分类名，近景再显示工具名

## 可复用的提示词

下面是依据学习记录重构的练习指令，便于从零复现观察到的效果。

> 做一个可直接打开的单文件 HTML 关系星图。用 1 个白色根节点连接 4 个分类中心，每个分类中心下放 5 个条目。点使用分类颜色，选中点显示光环。对每个条目写一句工作说明，对每条跨组线写一句实际用途。开场聚焦 Teams，再依次点亮办公组。进入设计组时，先拉远看清金色与橙色两个星团，然后推近新条目。选择列表项或星点时，同步更新详情、列表高亮和计数。远景优先展示分类名称。

## 可选技术与本项目取舍

| 环节 | 可学习的工具 | 交互成品的做法 |
| --- | --- | --- |
| 计算布局 | `d3-force-3d` 可计算三维力导向坐标，`3d-force-graph` 集成了布局与 Three.js 渲染。 | JavaScript 固定分类中心和随机种子，通过弹簧和斥力迭代得到 XYZ 坐标。 |
| 绘制星点 | Three.js 支持用材质和 Bloom 后处理制作光晕。 | 将三维坐标投影到 HTML Canvas 2D，每颗星叠加径向渐变、亮芯或选中环。 |
| 控制镜头 | Three.js 的 OrbitControls 提供旋转和缩放。 | 自有镜头控制处理拖动、滚轮、触摸和焦点过渡。 |
